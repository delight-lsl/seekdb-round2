# MiniVectorDB 架构设计文档

## 1. 系统定位与约束

- **运行模式**：单机、单进程、单客户端、stdin/stdout JSONL 协议（兼容 `--read-only` 根文件系统，仅 `/data` 可写）。
- **并发与事务**：最多一个显式事务；语句级原子性；自动提交语句即单语句事务。
- **内存约束**：内存镜像预算取容器内存上限的 1/4（≤ 512 MiB）；超出预算的表转为磁盘模式，不依赖全量载入内存。
- **持久化目录**：默认 `/data`（`--data-dir` 或 `VECTORDB_DATA_DIR` 可覆盖）。

## 2. 模块依赖与职责

```text
cli::protocol ──▶ sql::parser ──▶ sql::executor
                                      │
          ┌───────────────┬───────────┼─────────────────┐
          ▼               ▼           ▼                 ▼
   catalog::manager  transaction  storage::engine   recovery::{wal, redo, checkpoint}
                                      │
                         ┌────────────┼────────────┐
                         ▼            ▼            ▼
                  storage::file  storage::mem  vector::distance
                  (提交日志文件)  (列式内存镜像)  (SIMD 内核)
```

1. **`cli/protocol.rs`**：直接对 fd 0/1 做 `read`/`write` 的行协议循环。请求行用 SSE2 找换行，JSON 零拷贝反序列化（`sql` 字段借用输入缓冲区）；每个响应序列化到复用缓冲区后一次 `write` 发出。应答后短暂轮询标准输入等待下一请求。
2. **`sql/`**：零拷贝词法/语法分析（`Token<'a>` 与 `Statement<'a>` 直接借用输入 SQL 缓冲区切片，消除标识符、数字与无转义字符串字面量的堆分配）；`executor.rs` 负责类型与约束校验、自动提交批量插入的零中间对象直写快路径（`insert_autocommit_raw`）、事务写集叠加、过滤掩码生成、复用 `QueryScratch` 的 TopK 执行与结果投影。向量文本由手写 SWAR 扫描器直接追加解析到复用缓冲区（结果与标准库解析逐位一致，无法确认的记号回退到标准库）。
3. **`catalog/`**：表与向量索引元数据，事务内 DDL 暂存、回滚丢弃。
4. **`storage/`**
   - `file.rs`：表数据文件（提交日志）。追加组 → `fdatasync` → `posix_fadvise(DONTNEED)` 释放页缓存；容错顺序扫描（恢复用）与严格顺序扫描（磁盘模式查询用）。
   - `mem.rs`：列式内存镜像 `MemTable`（定长块向量列、带 ≤254 字典去重与 1-byte `tags` 过滤的字符串字节池、整数列）与 7-bit 量化下界码 `SqCodes`；精确 TopK 的三遍扫描与 `QueryScratch` 缓冲区复用在这里实现。
   - `engine.rs`：`DiskTable` 把文件与镜像组合起来：`insert_autocommit_raw` / `append_group`（落盘）→ `apply_group`（发布到内存）；连续 `RowId` 密集数组映射 `SlotMap`、内存预算、磁盘模式（位置表 + 流式扫描）、压缩到新代际。
5. **`vector/distance.rs`**：自研 AVX2/FMA 内核（运行时检测，均有标量回退）：双精度精确平方距离、单精度候选扫描、4 行展开 `_mm256_hadd_epi32` 归约与寄存器驻留查询向量的 7-bit 量化下界计算、阈值筛选。
6. **`transaction/`**：单事务写集 `TxnWriteSet`（按表记录新增/修改/删除与主键增量）。
7. **`recovery/`**：`wal.rs`（DDL 与跨文件事务提交记录）、`redo.rs`（启动恢复）、`checkpoint.rs`（压缩、WAL 轮转、原子替换检查点）。

## 3. 关键路径

- **批量写入（自动提交）**：解析 → 校验（主键、长度、维度、有限性）→ 行帧直接编码进组缓冲区 → 一次 `pwrite` + 一次 `fdatasync` → 发布到内存镜像 → 应答。行数据全程只落盘一份。
- **向量 TopK**：解析查询向量 →（如有 `WHERE`）在列上生成掩码 → 量化下界扫描 → 取 K 个最小下界做精确距离得到阈值 → 对下界不超过阈值的行精确计算并排序 → 投影输出。
- **重启**：读检查点与 WAL → 顺序读每个表文件重建镜像（边读边释放页缓存）→ `ready`。

## 4. 复杂度

| 操作 | 时间 | 常驻内存 | 说明 |
| --- | --- | --- | --- |
| 主键查找 / 唯一性检查 | `O(1)` 均摊 | 约 40 B/行 | 两张整数键哈希表 |
| 向量 TopK（内存模式） | `O(N·D/4 字节)` 的整数下界扫描 + 少量精确距离 | 向量 `4·D` B/行 + 量化码 `D` B/行 | 结果精确 |
| 向量 TopK（磁盘模式） | `O(文件大小)` 顺序扫描 | 位置表约 45 B/行 | 页缓存可回收 |
| 提交 | `O(写集大小)` | — | 单表 1 次 `fdatasync`；多表为表数 + 1 次 |
| 恢复 | `O(数据文件大小 + WAL)` | 同上 | 幂等 |
