# MiniVectorDB 性能测试记录

测量环境：服务器本地 Docker（`--network=none --cpus=2 --memory=2g --read-only --cap-drop=ALL`），`/data` 绑定到独立 ext4 设备，使用官方 `protocol_check/_transport.py` 的 `Session` 逐请求收发（与判题方式一致）。负载按赛题 3.3 节：空表开始 100 批 × 100 行（10,000 × 128 维），随后 100 条预热 + 1,000 条 Top-10 查询（一半带 `category = ...` 等值过滤，约 10% 选择率），exact 模式，结果用 numpy 暴力真值逐条核对。

这些数字只说明同一台机器上两个版本的相对差异；正式成绩以平台测量为准。

## 1. 上一提交版（35a103b）与当前版对比（各 3 轮）

| 指标 | 上一版 | 当前版 | 说明 |
| --- | ---: | ---: | --- |
| 批量写入 T | 736 / 748 / 754 ms | 382 / 494 / 498 ms | 行数据只写一次；借用式 Lexer + `insert_autocommit_raw` 零中间 `Row`/`Vec<f32>` 分配；SWAR 向量解析 |
| 1,000 条查询 T | 515 / 1113 / 1176 ms | 312 / 355 / 359 ms | 列式内存镜像 + 1-byte 字典过滤 + 4 行 `_mm256_hadd_epi32` 量化下界扫描 + `QueryScratch` 复用；请求间短轮询 |
| `CREATE VECTOR INDEX` | 约 2,350 ms | 约 2 ms | 量化码惰性建立（首次检索约 1–2 ms） |
| 物理写入字节（进程 `write_bytes`） | 11.30 MiB | 5.47 MiB | 去掉 WAL 双写，组尾 4 KiB 对齐 |
| 容器峰值内存（cgroup） | 31.4–31.6 MiB | 7.5–8.5 MiB | 单份向量、写后释放页缓存、密集 `SlotMap`、字符串字典去重、静态链接、无图索引 |
| Recall@10（无过滤 / 有过滤） | 1.0 / 1.0 | 1.0 / 1.0 | 两版均为精确结果，1000/1000 条与真值完全一致 |

单请求往返里 Docker 传输约占 0.2 ms（空操作请求实测），是当前查询耗时的主要部分。

## 2. 其他规模

| 场景 | 结果 |
| --- | --- |
| 12 万行 × 128 维，`--memory=2g`（内存模式） | 写入 5.55 s；查询均值 1.9 ms；峰值 89 MiB；结果全部正确 |
| 12 万行 × 128 维，`--memory=128m`（自动转磁盘模式） | 写入 5.65 s；查询均值 35.6 ms；峰值 78 MiB（其中页缓存 65.6 MiB，可回收）；结果全部正确；重启后 12 万行 |

## 3. 可调项

| 环境变量 | 默认 | 含义 |
| --- | --- | --- |
| `MVDB_SYNC` | `full` | 提交持久化方式：`full` = `fdatasync`；`range` = `sync_file_range` 写入并等待；`off` = 交给内核回写。后两者不保证断电持久化，默认不启用。同机实测 `range` 使批量写入 T 再降约 30%。 |
| `MVDB_SPIN_US` | `2000` | 应答后轮询标准输入等待下一请求的最长时间（微秒），`0` 关闭。同机 Docker 下查询 T 降约 10–20%。 |
| `MVDB_MEM_BUDGET_MB` | 容器内存上限的 1/4（≤ 512） | 内存镜像预算，超出后表转为磁盘模式。 |
